1. REPOSITORY AUDIT & DISCOVERABILITY BASELINE
================================================================================
- Organization: ellmos-ai
- Ecosystem: open-bricks (umbrella)
- Target Audience: Multi-device developers, AI agent system architects, offline-first engineers, multi-machine operators, infrastructure reliability teams
- Core Positioning: A serverless cross-machine sync protocol and transfer yard for people and AI agents operating across multiple workstations, laptops, and home servers.
- Distinct Value Proposition: Zero cloud daemon dependency. Operates across any sync provider (OneDrive, Dropbox, Syncthing, NAS, git) using three strict invariants: the Machine-Owned Slot Rule (no merge conflicts by design), a Gated Daily Sync Ritual (2-5 min idempotent run), and a Declarative Bootstrap Runbook.
- Sibling Ecosystem Integration: Core sync federation pillar in the ellmos infrastructure suite alongside lock-master (locks & leases), ticket-master (task routing), and sqlite-transit-sync (database showcase transit).

================================================================================
2. TARGET PERSONAS & USER JOURNEYS
================================================================================
1. Multi-Device Developers & Distributed AI Engineers
   - Needs: Work seamlessly across laptop, desktop, and home lab without losing state, diverging branches, or overwriting work.
   - Pain Points: Traditional cloud file sync silently creates chaotic conflicted copies (`file (1).txt`, `file-WORKSTATION.txt`) or corrupts active databases and lock files.
   - system-gap-master Solution: Dedicated machine slots (`hosts/<host>/`), atomic delete-after-read messages (`messages/`), and safe policy-driven conflict-copy reconciliation.

2. Autonomous AI Agent Architects & Fleet Coordinators
   - Needs: Coordinate multi-agent swarms (Claude, Codex, Antigravity/Gemini) across independent physical hosts without central cloud servers or open ingress ports.
   - Pain Points: Cloud LLMOps frameworks require complex API gateways, open inbound firewall ports, and introduce single points of failure.
   - system-gap-master Solution: Serverless transfer yard using plain human-readable Markdown and JSON files. Agents communicate via file drops and execute gated daily syncs idempotently.

3. Offline-First Infrastructure & DevOps Engineers
   - Needs: Resilient, reproducible machine bootstrapping and cross-host state coordination that works fully offline or over intermittent LAN/VPN links.
   - Pain Points: Heavyweight cluster orchestrators (Kubernetes, Consul) are overkill for developer workstations and fail completely when offline.
   - system-gap-master Solution: 100% Local-First / Zero-Egress, unprivileged RunAsInvoker operation, and self-contained yard templates capable of bringing up a fresh host from the yard alone.

4. Enterprise Security, Privacy & Compliance Officers
   - Needs: Guarantee zero telemetry egress, strict file access boundaries, zero credential persistence in sync areas, and deterministic disaster recovery.
   - Pain Points: Commercial sync tools transmit proprietary telemetry or risk syncing secrets into cloud storage.
   - system-gap-master Solution: Rule 6 zero-secrets invariant, signed trusted-peer SFTP transfer preparation, 100% permissive open-source stack audited in THIRD_PARTY_LICENSES.md, and dual security SLAs (48h response, 5-day triage).

5. GOVERNANCE & RUNTIME INVARIANTS (INV-LOCAL-01 TO INV-SLA-10)
================================================================================
- INV-LOCAL-01: 100% Local-First & Zero Egress (operates entirely on local filesystems; zero cloud telemetry or tracking)
- INV-SEC-02: Non-Elevation & User Mode (unprivileged RunAsInvoker execution without root/administrator privileges)
- INV-SLOT-03: Machine-Owned Slot Isolation (each host writes only to its own slot hosts/<host>/; foreign slots are read-only)
- INV-MSG-04: Delete-After-Read Direct Messaging (inter-machine messages are atomically consumed and removed)
- INV-FAIL-05: Fail-Closed Locking & Lease Enforcement (reconciler and transfer operations require valid exclusive kernel leases)
- INV-MERGE-06: Deterministic 3-Way & Append-Only Reconciliation (safe conflict resolution without data destruction)
- INV-GATE-07: Gated Preflight & Idempotent Daily Ritual (once-per-day execution verified in DAILY_SYNC_LOG.md)
- INV-PEER-08: Cryptographically Bound SFTP & Detached Verification (detached signatures and sha256 checksums required)
- INV-LIC-09: 100% Permissive Audited Dependency Stack (clean MIT/PSFL stack audited in THIRD_PARTY_LICENSES.md)
- INV-SLA-10: Cryptographic Parity & Dual Security SLA (48-hour response and 5-day triage commitment)
